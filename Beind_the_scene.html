1. Execution Context

Execution Context ek environment hota hai jahan JavaScript code ko execute/run kiya jata hai.

Simple words: JavaScript jab code run karti hai, to variables, functions aur code ko manage karne ke liye ek environment create hota hai. Isay Execution Context kehte hain.

Types

  1. Global Execution Context
  2. Function Execution Context
  3. Eval Execution Context — rarely used

2. Global Execution Context

Jab JavaScript script run hoti hai, sabse pehle Global Execution Context create hota hai.

const name = "Ali";

function greet() {
  console.log("Hello");
}

greet();
Important: Global Execution Context sabse pehle create hota hai.

3. Execution Context ke 2 Phases

Phase 1 — Creation

JavaScript environment prepare karti hai. Variables/functions register hote hain, scope-related information set hoti hai aur this ki value determine hoti hai.

Phase 2 — Execution

Ab actual code execute hota hai aur assignments/function calls perform hote hain.

let age = 20;
console.log(age);

4. Call Stack

Call Stack JavaScript ka mechanism hai jo track karta hai ke kaunsa function currently execute ho raha hai.

LIFO: Last In, First Out
function first() {
  second();
}

function second() {
  third();
}

function third() {
  console.log("Hello");
}

first();

Flow: Global → first() → second() → third(). Third complete hoga to stack se remove, phir second, phir first.

Stack Overflow

function test() {
  test();
}
test();

Infinite recursive calls eventually Maximum call stack size exceeded error de sakti hain.

5. Scope

Scope ka matlab hai code ke kis part mein koi variable accessible hai.

const name = "Ali";

function greet() {
  console.log(name);
}

Yahan name function ke andar accessible hai kyunki woh outer scope mein hai.

6. Types of Scope

Global Scope

const name = "Ali";
console.log(name);

Function Scope

function test() {
  const age = 20;
  console.log(age);
}

// console.log(age); // Error

Block Scope

if (true) {
  let age = 20;
  const name = "Ali";
}

// console.log(age); // Error

7. Scope Chain

Agar variable current scope mein nahi milta, JavaScript outer scope mein search karti hai.

const country = "Pakistan";

function outer() {
  const city = "Karachi";

  function inner() {
    const name = "Ali";

    console.log(name);
    console.log(city);
    console.log(country);
  }

  inner();
}

outer();

inner() pehle apne scope, phir outer(), phir global scope mein search karta hai.

Rule: Inner scope outer variables access kar sakta hai, lekin outer scope normally inner scope ke variables access nahi kar sakta.

8. Lexical Scoping

JavaScript lexically scoped language hai.

Function ko variables ka access uski code mein position se determine hota hai, na ke function ko kahan se call kiya gaya.

const name = "Ali";

function greet() {
  console.log(name);
}

9. Hoisting

Hoisting ka matlab hai JavaScript execution se pehle declarations ko apne scope/environment mein register karti hai.

console.log(x);
var x = 10;

// Output: undefined
Important: Hoisting ka matlab literally code ko upar move karna nahi hai. Ye conceptual model hai jo creation phase mein declarations ko process hone ko explain karta hai.

Function Hoisting

greet();

function greet() {
  console.log("Hello");
}

// Output: Hello

10. Temporal Dead Zone — TDZ

TDZ woh period hai jab let/const binding scope mein exist karti hai lekin declaration/initialization se pehle access nahi ki ja sakti.

console.log(age);

let age = 20;

// ReferenceError
let/const declaration → TDZ → initialization → usable

11. The this Keyword

this ek special keyword hai. Regular functions mein iska value generally function ko kis tarah call kiya gaya is se determine hota hai.

const student = {
  name: "Ali",

  greet() {
    console.log(this.name);
  }
};

student.greet();

// Output: Ali
Object method ko student.greet() ki tarah call karne par method ke andar this us object ko refer karta hai.

Regular Function

const student = {
  name: "Ali",
  greet: function () {
    console.log(this.name);
  }
};

student.greet(); // Ali

Arrow Function

const student = {
  name: "Ali",
  greet: () => {
    console.log(this.name);
  }
};

Arrow function ka apna this nahi hota; woh surrounding lexical this use karta hai.

14. Object References

Objects reference values hote hain. Assignment se same object ka reference share ho sakta hai.

const student1 = {
  name: "Ali"
};

const student2 = student1;

student2.name = "Ahmed";

console.log(student1.name);
// Ahmed
Dono variables same object ko refer kar rahe hain.

Primitive Copy

let a = 10;
let b = a;

b = 20;

console.log(a); // 10
console.log(b); // 20

15. Shallow Copy vs Deep Copy

Shallow Copy

New outer object banta hai, lekin nested objects/arrays ke references share ho sakte hain.

const user1 = {
  name: "Ali",
  age: 20
};

const user2 = { ...user1 };

user2.name = "Ahmed";

console.log(user1.name);
// Ali

Nested Object Problem

const user1 = {
  name: "Ali",
  address: {
    city: "Karachi"
  }
};

const user2 = { ...user1 };

user2.address.city = "Lahore";

console.log(user1.address.city);
// Lahore

Deep Copy

Modern JavaScript mein structuredClone() nested data ko deeply clone karne ke liye useful hai.

const user2 = structuredClone(user1);

user2.address.city = "Lahore";

console.log(user1.address.city);
// Karachi

Outer object newOuter + nested data independently cloned
Nested references share ho sakte hainNested references share nahi kiye jate
{ ...obj }structuredClone(obj)

16. Memory Management

JavaScript automatically memory manage karti hai. Is process mein Garbage Collection important role play karti hai.

let user = {
  name: "Ali"
};

user = null;

Agar object ka koi aur reachable reference nahi hai, to woh garbage collection ke liye eligible ho sakta hai.

Stack vs Heap — Conceptual Model

Stack

Execution-related information aur local bindings ko samajhne ke liye useful conceptual model.

Heap

Objects aur dynamically allocated data ke liye memory area ka conceptual model.

Actual JavaScript engines ki memory implementation simple “primitives = stack, objects = heap” rule se zyada complex hoti hai.

17. Complete Flow — Sab Concepts Ek Sath

const name = "Ali";

function greet() {
  const message = `Hello ${name}`;

  function sayHello() {
    console.log(message);
  }

  sayHello();
}

greet();
  1. Global Execution Context create hota hai.
  2. name aur greet environment mein register hote hain.
  3. Global code execute hota hai.
  4. greet() call hota hai.
  5. Function Execution Context create hota hai.
  6. message create hota hai.
  7. sayHello() call hota hai.
  8. Naya execution context create hota hai.
  9. sayHello() scope chain se message access karta hai.
  10. console.log() execute hota hai.
  11. sayHello() stack se remove hota hai.
  12. greet() stack se remove hota hai.
